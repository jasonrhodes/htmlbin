THIS WEEK — NOTABLE

Severity ADR & Workflow extension service

Severity ADR — closed rna#462

Decision: first-class severity

We’ve landed the architecture decision for critical / high / medium / low severity as a first-class concept. Convention, engine integration, and routing strategy are decided.

What this unblocks

Action policy routing by severity level. UI surfacing of severity in episodes table and rule details. Rule authoring forms can expose the severity field with clear semantics.

Also closed this week

rna#449 Orphan rule tasks (fire forever bug) fixed. rna#460 evaluateKql error handling. rna#275 YAML ↔ GUI sync.

Workflow extension service — merged #267924

New WorkflowExtensionsService

The alerting v2 plugin now has a service for registering workflow triggers and steps. This is the foundation for the workflow integration epic (rna#445) — enabling episode-driven workflow automation.

What’s next

Consumers register triggers via the service. Episodes can emit workflow events. Initial target: incident management and escalation flows triggered by episode state changes.

Closed in rna-program

rna#446 Create a workflow service — done. rna#445 Epic continues; this was the foundational step.
